# 📋 システム仕様書: Immich Smart Cleaner (仮称)

## 1. システム概要

本システムは、セルフホストされたImmichのAPIと連携し、CLIP（セマンティック検索）を利用して品質の低い画像や不要な画像を抽出し、一括でゴミ箱へ移動・整理するためのWebアプリケーションである。
独自の状態管理（フィルタリング対象外の追跡など）のためにローカルのSQLiteデータベースを内蔵し、単一のDockerコンテナとして起動する。

### ⚙️ 動作環境・技術スタック（推奨）

- **稼働形態:** Dockerコンテナ（単一コンテナ構成）
- **公開ポート:** `2293`
- **バックエンド:** SvelteKit
- **フロントエンド:** HTML5 / Vanilla CSS / SvelteKit
- **データベース:** SQLite 3 (コンテナ内にボリュームマウント)

## 2. システム構成とデータフロー

```
[ ユーザー (ブラウザ: 2293) ]
       │  ▲
       │  │ (UI表示、操作、コンテキストメニュー)
       ▼  │
[ 本システム (Backend & SQLite) ]
```

### 🔓 必要な環境変数 (ENV)

コンテナ起動時に以下の環境変数を必要とする。

- `IMMICH_URL`: ImmichサーバーのベースURL (例: `http://192.168.1.10:2283`)
- `IMMICH_API_KEY`: Immichの管理画面から発行したAPIキー

## 3. データベース設計 (SQLite)

Immich側で「一度ゴミ箱から救出された画像」や、ユーザーが「明示的に対象外とした画像」を記憶し、再度のフィルタリングから除外するために、ローカルSQLiteを使用する。

### `excluded_assets` テーブル

| カラム名     | 型       | 制約                      | 説明                                                           |
| ------------ | -------- | ------------------------- | -------------------------------------------------------------- |
| `asset_id`   | TEXT     | PRIMARY KEY               | Immich側のアセット一意ID                                       |
| `reason`     | TEXT     | DEFAULT 'manual'          | 除外された理由 (`manual`: 手動変更, `rescued`: ゴミ箱から救出) |
| `updated_at` | DATETIME | DEFAULT CURRENT_TIMESTAMP | 最終更新日時                                                   |

## 4. 画面レイアウト・UI/UX仕様

画面は大きく「① 上部キーワードバー」「② 左側コントロールパネル（固定）」「③ メイン表示エリア」の3つで構成する。

### 📱 画面配置イメージ

```
+------------------------------------------------------------------------------------+
| [blurry photo] [screenshot] [receipt] [document] [price tag] ... (キーワード群)     |
+------------------------------------------------------------------------------------+
| [左パネル(固定)] | [メイン表示エリア]                                                 |
|                 |                                                                  |
| ■ ページネーション|  (1列のリスト配置。スコア降順)                                      |
|   [<] [ 1 ] [>] |                                                                  |
|   Total: 500 px |  +-------------------------------------------------------------+ |
|   Per Page: [100]|  | [サムネイル]  Score: 0.895                                   | |
|                 |  |               [タグ: フィルタリング対象外] (非表示トグルがON時) | |
| ■ 閾値設定       |  +-------------------------------------------------------------+ |
|   Threshold:    |  +-------------------------------------------------------------+ |
|   [ 0.75 ] (1-0)|  | [サムネイル]  Score: 0.821                                   | |
|                 |  |                                                             | |
| ■ アクション     |  +-------------------------------------------------------------+ |
|   [一括ゴミ箱移動]|  | ...                                                         | |
|                 |                                                                  |
| ■ 表示フィルタ   |                                                                  |
|   [x] 対象外含む |                                                                  |
+-----------------+------------------------------------------------------------------+

```

### ① 上部キーワードバー

- 前述の低重要度画像用キーワードをボタンとして水平に羅列する。
- **初期プリセット（例）:** `blurry photo`, `screenshot`, `receipt`, `document`, `accidental photo`, `price tag`, `too dark`
- ボタンをクリックすると、即座にそのキーワードでImmichに対してCLIP検索が実行される。

### ② 左側コントロールパネル（固定配置：`position: fixed`）

- **ページネーション情報:**
- `[<]`（前へ） `[入力欄]` `[>]`（次へ）のボタン。入力欄に数値を直接入れてEnterでページ遷移。
- 「合計ページ数」「現在のページ数」「合計画像数」の表示。
- 「1ページあたりの画像数」の変更用 `<input type="number">`（初期値: 100）。変更時に即座に再描画。

- **閾値（Threshold）設定:**
- 数値入力用の `<input type="number" step="0.01" min="0" max="1">`。
- ここで設定した閾値は、後述の「一括ゴミ箱移動」の基準として使用される。

- **アクションボタン:**
- `[閾値を超えた画像を設定通りゴミ箱に移動]` ボタン。危険な操作のため、クリック時に確認ダイアログ（コンファーム）を表示する。

- **表示フィルタ設定:**
- 「フィルタリング対象外の画像を表示する」チェックボックス（トグル）。
- OFFの場合：SQLiteに登録されているアセットはメインエリアに表示されない。
- ONの場合：SQLiteに登録されているアセットも表示されるが、「対象外」のバッジ（タグ）が付与される。

### ③ メイン表示エリア

- **配置:** 指示に基づき、「画像とスコアのペアを1列（1カラムの縦並びリスト）」で配置する。
- **表示内容:**
- Immichから取得したサムネイル画像（遅延読み込み/Lazy Load対応を推奨）。
- CLIP検索の適合スコア（例: `Score: 0.785`）。
- SQLiteで「対象外」に設定されている画像には、画像内に重なるように `[フィルタリング対象外]` という目立つバッジ（タグUI）を表示。

- **右クリックコンテキストメニュー（独自実装）:**
- 画像の上で右クリックした際、ブラウザ標準のメニューを禁止し、カスタムメニューを表示する。
- メニュー項目: `[フィルタリング対象外に設定 / 対象に戻す]`
- クリックすると、非同期でローカルSQLiteのデータを書き換え、UI上のバッジ状態をトグルする。

## 5. バックエンド処理ロジック & API連携仕様

### 5.1 CLIP検索の実行 (`POST /api/search/smart`)

ユーザーがキーワードボタンを押した際、バックエンドはImmich APIのスマート検索エンドポイントを叩く。

- **リクエスト先:** `POST {IMMICH_URL}/api/search/smart`
- **Payload（例）:**

```json
{
  "query": "ユーザーが選択したキーワード",
  "size": 1000,
  "withExif": true
}
```

_(注: 全体像を把握しスコア順に並べるため、一度に多めのアセットを取得し、バックエンドのメモリまたはSQLiteの一時テーブルでページネーションを処理するアプローチを推奨)_

- **フィルタリングロジック:**
- レスポンスデータから、`type` が `"IMAGE"` のもののみを残し、`"VIDEO"` はすべて除外する。
- 結果を `score`（信頼度係数）の降順（高い順）でソートする。

### 5.2 ページネーションとSQLiteの結合

1. Immichから取得した「動画除外済み・スコア降順リスト」のアセットID群について、ローカルSQLiteの `excluded_assets` テーブルにIDが存在するか確認する。
1. 「対象外を表示しない」設定の場合、SQLiteに存在するアセットを配列から除外する。
1. 指定されたページ（1ページ100枚など）の範囲を切り出し、フロントエンドに返す。

### 5.3 一括ゴミ箱移動処理 (`PUT /api/assets`)

ユーザーが「自動でゴミ箱に移動」を実行した場合の処理：

1. 現在選択されているキーワードの全検索結果（または現在表示中のページ）のうち、「設定された閾値以上のスコア」**を持ち、かつ**「SQLiteの除外リストに入っていない」アセットIDを全て抽出する。
1. Immichのバルク更新APIを呼び出す。

- **リクエスト先:** `PUT {IMMICH_URL}/api/assets`
- **Payload:**

```json
{
  "ids": ["asset-id-1", "asset-id-2", "..."],
  "isDeleted": true
}
```

### 5.4 救出された画像の自動タグ付け（同期処理）

「削除された画像を手動でゴミ箱から救出した場合」の検知ロジック：

- **アプローチ:** シンプルに、本アプリで「一括ゴミ箱移動」を実行したアセットIDの一覧を別テーブルに保存しておき、次回の検索時にそれらが `isDeleted: false` で戻っていたら、手動救出されたとみなして自動的に `excluded_assets` に `reason='rescued'` として登録する。\*\*

## 6. Docker環境構成仕様

ローカル環境で独立して即座に起動できるよう、以下のDocker構成とする。

### `Dockerfile` (イメージ作成例)

```dockerfile
FROM python:3.11-slim

WORKDIR /app

# 依存関係のインストール
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

# ソースコードのコピー
COPY . .

# SQLite用のデータディレクトリを作成
RUN mkdir -p /app/data

EXPOSE 2293

CMD ["python", "main.py"]

```

### `docker-compose.yml` (ユーザー提供用サンプル)

```yaml
version: "3.8"

services:
  immich-cleaner:
    build: .
    container_name: immich-cleaner
    ports:
      - "2293:2293"
    environment:
      - IMMICH_URL=http://your-immich-ip:2283
      - IMMICH_API_KEY=your_secret_api_key_here
    volumes:
      - ./cleaner_data:/app/data
    restart: always
```

## 7. 開発・実装上の注意点（エッジケース対策）

1. **サムネイル画像のプロキシ:**
   ブラウザから直接ImmichのサムネイルURL（`/api/assets/{id}/thumbnail`）を読み込む場合、APIキーをリクエストヘッダー（`x-api-key`）に含める必要がある。フロントエンドにAPIキーを露出させないため、またクロスドメイン（CORS）問題を回避するため、**本アプリのバックエンド（ポート2293）がサムネイル画像をプロキシするエンドポイント（例: `/api/proxy/thumbnail/{id}`）を実装すること。**
1. **Immich APIのバージョン追従:**
   Immichはアップデート頻度が高く、API仕様が変更されることがある。アセット削除（`isDeleted: true`）やスマート検索のエンドポイントの仕様は、稼働させるImmichのバージョンに合わせてエンドポイントパスを調整できるように、バックエンドの通信モジュールを疎結合にしておくこと。
